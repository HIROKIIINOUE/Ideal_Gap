# 要件定義

## 1,プロジェクト概要

### 1-1, プロジェクト名

Ideal Gap (仮名)

### 1-2, 目的

ユーザーが理想の自分に近づけるための手助けをするアプリ。具体的には以下 4 点。

- 理想の自分の姿を知る(現在と理想のギャップを知る)
- 理想への正しい道標を可視化する(ギャップを埋めるための道のりを知る)
- 理想へ近づくための継続的タスク管理(ギャップを埋めるための努力を管理する)
- 理想達成のためにタスクへの集中を加速(その努力の集中力を上げる)

### 1-3, ユーザーターゲット

- 幸せに生きたい人
- 理想の自分になりたい人
- モチベーションを上げたい人
- 物事を継続したい人
- 自己研鑽に没頭したい人
- iPhone(Android)、iPad(その他タブレット)を使用している人
- 日本語話者、英語話者、フランス語話者

### 1-4 アプリの特徴

- iOS / Android のモバイルアプリ(将来的にタブレット最適化)
- シンプルで使いやすい
- モダンでスタイリッシュな UI
- UI/UX でモチベーションアップを狙う
- 各機能でユーザーの継続力・集中力を促進
- 日本語、英語、フランス語対応

### 2-1,サインアップ・ログインページ

### 2-2-1,サインアップページ(フロント)

ユーザーに以下情報を入力してもらう。
デフォルト言語はサインアップ完了時にユーザが使用している言語。
タイムゾーンはサインアップ完了時にユーザの iPhone 設定と連動。(実装が難しければ手動)

(その場合 confirm ポップアップを出現させ、ユーザに明確に説明した上でユーザの承認を得る)

- ユーザ名
- メールアドレス
- パスワード
- 支払い方法(必要に応じて別リンクへ遷移)

### 2-2-2,サインアップページ(バック データベース)

Supabase Auth で「id」サインアップ時の「ユーザ名」「メールアドレス」「パスワード」を保持。
Supabase DB における users テーブル内の「id」は Auth の id と一致、「ユーザ名」「メールアドレス」も Auth の各データと同期させる。(ユーザ名とメールアドレスを変更可能にするため)
課金状態は Supabase DB における subscriptions テーブルで管理。
こちらで有料機能を開放するかを判定。(課金状態=アクティブ && ユーザログイン済み)
二度目の初月無料防止策として、DB 内の user テーブルに is_canceled フラグを作成し、ユーザ退会後もユーザデータを保持、再サインアップ時には実質「再アクティブ化」として is_canceled を false に変更する。また、再アクティブ時に user テーブル内の had_account_before をチェックし、true なら初月無料対象外

### 2-2-3,サインアップページ(バック 決済ロジック)

ユーザの決済手段・情報は本 PJ システムでは一切扱わない。
ユーザーは Apple ID / Google アカウントの支払い情報を使い、カード変更・削除も App Store / Google Play の設定画面で行う。

**【決済ロジック】**
ユーザがアプリ内の該当ボタン押下時に RevenueCat SDK を使って App Store / Google Play の課金フロー遷移される。→ 購入が成功するとレシートが発行される →RevenueCat SDK がそのレシートを RevenueCat サーバーに送る。→ そのレシートをもとに「ユーザが何をいつまで持っているか」を RevenueCat が管理。→Supabase DB のユーザサブスクリプション状態が更新される。

つまり revenueCat 決済ステータス変更時に DB 側で subscriptions テーブルが作成・更新される。
subscriptions 内の user_id は Supabase の UID と紐づける。
各支払期日に Apple / Google が自動で課金、RevenueCat が成否を監視、結果ステータスが変更したタイミングで RevenueCat → Webhook → DB と伝達、subscriptions が更新される。(「Status をアクティブに」や「current_period_end(次回支払日)」など)
解約は「解約する」ボタン押下時に Apple ストア/Android ストアに遷移させる。
ストアで解約すると RevenueCat のサブスクもキャンセル状態に。
そのタイミングで Supabase DB 更新。(subscriptions.cancel_at_period_end = true など) 有効期限までは status="active"のままだが、期限を過ぎたタイミングで revenueCat が status="canceled"に更新、DB にも status="canceled"を反映。アプリ自体は status を見て有料機能をロックにする

### 2-2-4,サインアップページ(バック セキュリティ)

【悪意あるユーザが「課金中」と偽装するリクエストを送る可能性】
RevenueCat の Webhook 署名・シークレットキーを用いてリクエストの正当性を検証、Supabase Edge Functions で署名チェックを実装 → サーバー側(Supabase)で生のリクエストボディと環境変数に置いたシークレットキーを使って HMAC で署名を再計算 → 計算結果とヘッダー値が一致するかを比較 → 一致の場合は本物の RevenueCat で対応、不一致の場合は偽リクエストとして 401/403 で拒否

【別ユーザのトークンで課金情報にアクセスできてしまう可能性】
・常に「現在ログインしている Supabase Auth UID」と subscriptions.user_id を比較
・RLS（行レベルセキュリティ）で「user_id が current_user.id の行しか読めない」ようにする。
つまりユーザーのアプリ → anon / authenticated ロール → RLS 有効 → 自分の行しか触れない。
バックエンド（Webhook）→ service_role → 管理者として全行を更新できる。
auth.uid() や auth.role()を使用して本人だけアクセス可能ポリシーを作成

### 2-7,理想の自分ページ

ユーザが「なりたい姿」を複数作成し、複数データを箇条書きで表示。
ページ上部に「追加」「削除」ボタンを配置。
追加ボタンを押すとインプットモーダルが出現し、そこに本文を打ち込める。
空文字は制御し、1 文字以上入力するとボタン押下が可能になる。
作成されたデータはリストとして表示される、1 データ 1 行。
データは user_ideal として DB に挿入される。（構造は data-structure.md を参照）
各行カードはクリックすると本文を更新するためのインプットモーダル(「追加」と同じデザイン)が出現し、本文を更新することができる。
各行カードの右側にはコントロールボタンを配置し、そのコントロールボタンを長押し+ドラッグすることでリストの順番を変えることができる。
削除ボタンを押すと各行カードのコントロールボタンが削除ボタンに変更になり、ユーザが削除ボタンを押すと該当の行が削除される。（削除時はユーザに Confirm を求める）
削除作業中は「削除」ボタンの文言がわかりやすい文言（検討中）に変更され、押下すると元の行＋コントロールボタンの表示に戻る。

- なりたい姿作成機能
- なりたい姿リスト表示機能
- なりたい姿編集機能
- なりたい姿削除機能
- 表示されたリストをドラッグで位置変更する機能

### 2-8, 年間目標ページ

ユーザが「なりたい姿」をもとに年間目標を設定。
ユーザはカレンダー年(1/1〜12/31)1 年分のみデータの CRUD 操作可能。
今年の年間目標は 1 つ 1 つがカテゴリーとなっており、各月の月間目標に紐づいている。
紐づいた月間目標に積み上げられた作業時間をもとに各年間目標に費やした時間の割合を計算、円グラフとして年間目標ページに表示させる。
\*\*\*\*そうすることで各年間目標を均等に達成できるようにバランスよく月間目標を整理できる。

- 年間目標作成機能
- 年間目標リスト表示機能
- 年間目標編集機能
- 年間目標削除機能
- 年間目標リストをドラッグで位置変更する機能
- 各年間目標をカテゴリーラベルとして各月の月間目標に付与する機能
- 各月の各月間目標の作業時間をもとに紐づいた 1 つの年間目標の作業時間を計算
- 各年間目標に積み上げられた作業時間の割合を計算し円グラフを作成、表示

### 2-9, 月間目標ページ

「年間目標」をもとにユーザが月間目標を設定。
各月間目標に作業目標時間数を数値で設定。
12 か月分の月間目標を管理可能。画面上部で月の表示を変更できる。
各月の各月間目標は年間目標 1 つと紐づいており、各月間目標に積み上げられた作業時間データは紐づいた年間目標に吸い上げられる。
各月の各月間目標は 1 つ 1 つがカテゴリーとなっており、各週間タスクに紐づいている。
各週間タスクの作業時間に応じて紐づいた各月の各月間目標の作業時間が積み上げられる。
ここで積み上げられた月間作業時間は紐づいた年間目標に積み上げられる。
各月の各月間目標で指定した作業必要時間数とその月間目標に紐づいた複数の週間目標タスクの作業時間数で達成度を計測。
計算された達成度に応じてゲージバー(プログレスバー)が生成、各月の各月間目標の下部に表示される。
※達成度の計算は「タイマー終了時」などイベント発火時に行い、DB に保存した値をゲージバー(プログレスバー)で表示する。(不要な再レンダリングを防ぐため)

- 月間目標作成機能(達成目標時間数も指定)
- 月間目標リスト表示機能
- 月間目標編集機能
- 月間目標削除機能
- 月間目標リストをドラッグで位置変更する機能
- 各年間目標をカテゴリーラベルとして各月の各月間目標に付与する機能
- 各月の各月間目標の作業時間の合計が紐づいた年間目標に積み上げられる機能
- 各月の各月間目標リストを 1 カテゴリー(タスク A(〇月)など)とし、各週間タスクに紐づける機能
- 紐づけた週間タスクの作業時間を月間目標に積み上げる機能
- 積み上げられた作業時間と作業目標時間数で達成度を計測し、ゲージバー(プログレスバー)を生成して下部に表示する機能

### 2-10, 週間タスクページ

「月間目標」をもとにユーザが週間タスクを設定。
今週と来週メモの 2 ページを用意(上部のトグルボタンで切り替え)
ユーザが主にタスク管理で使用するのは今週ページ。
(週初めの定義はユーザに任せる)
来週メモは来週分の作業を洗い出すためのシンプルなメモ。
ユーザが週終わりに【来週タスクを今週タスクへ適用ボタン】1 つで「今週作業リストの削除 → 来週メモを今週タスクへ移行 → 来週メモをリセット」を行えるようにする
各週間タスクに目標時間を設定。
各タスクは 1 つの月の 1 つの月間目標と紐づいている。(何月と紐づけるかも設定)
タスクタイマーで計測した作業時間を指定されたタスク作業時間に積み上げる。
積み上げられて作業時間とそのタスクの作業時間目標をもとに週間達成度を計測、ゲージバー(プログレスバー)にして下部に表示。
各タスクの右側にはタスクタイマーページへ遷移するリンクボタンを設置。
(ここで遷移元のタスクがタスクタイマーに紐づいて作業時間に応じて積み上げられる)
ここで計測されたタスク作業時間はそのタスクに紐づく 1 つの月の 1 つの月間目標の作業時間に積み上げられる。
※達成度の計算は「タイマー終了時」などイベント発火時に行い、DB に保存した値をゲージバー(プログレスバー)で表示する。(不要な再レンダリングを防ぐため)
手動積み上げボタンを用意しアプリが使用できない期間に積み上げた時間も作業時間としてカウントできる。

- 週間タスク作成機能(目標時間数も指定)
- 週間タスクリスト表示機能
- 週間タスク編集機能
- 週間タスク削除機能
- 週間リストをドラッグで位置変更する機能
- 複数週間タスクと１つの月の１つの月間目標の紐づけ機能
- 各週間タスク下部に達成度を表すゲージバー(プログレスバー)表示機能
- 各週間タスク右側にタスクタイマーへ遷移するリンクボタン
- タスクタイマーの計測時間に応じてその週間タスクの作業時間が積み上げられる
- 積み上げられた作業時間の合計を計測する機能
- 作業時間と設定された目標時間を基に達成度を表す週間タスク用ゲージバー(プログレスバー)を作成、各タスクの下部に表示
- 積み上げられた作業時間をタスクと紐づく月間目標にも積み上げ、月間目標用ゲージバー(プログレスバー)にも適用。
- タスク時間手動積み上げ機能(アプリ未使用時の自己研鑽も記録に残せるように)
- タスク時間手動積み上げ機能は週間タスクページ最下部にボタンを用意し別途専用ページへ遷移

### 2-11 タスクタイマー機能

ユーザが各週間タスクの作業中に作業時間を計測するタイマー。
機能ページオープン時にユーザがタスク目標時間を決め、カウントダウンで残り時間を表示。
カウントダウン一旦停止/再開ボタンあり。
カウントが 0 になった時点でアラーム。
作業時間が記録され、関連する週間タスク、月間目標に積み上げられる。
また、音楽の再生/停止ボタンも画面に表示。
タスク集中音楽機能への遷移ボタンも表示。(音楽の選択が容易に行える)
タスクタイマーページにいる間、音楽は無限ループされる。
バックグラウンド遷移時もカウント継続（OS の制約範囲内）
タスク目標時間設定後も ±5 分単位で手動修正できる

- タスク目標時間設定
- 目標時間までの残り時間をカウントダウン式で表示
- カウントダウン完了時にアラーム
- 作業時間を関連する週間タスク、月間タスクに積み上げる
- カウントダウンは一時停止/再開ボタン操作可能
- タスク集中音楽の再生ボタンと一時停止ボタンあり
- タスク集中音楽の DL/変更のページへの遷移ボタンあり
- タスク集中音楽の無限ループ

### 2-12, 週間タスク手動積み上げ機能

ユーザがアプリを使用できない時間に積み上げた作業を手動で入力できる。
該当の週間タスクを手動で入力し、作業時間も手動で入力できる。

タスクタイマー用の音楽選定はいつでも自由に可能。

- タスク集中音楽のダウンロード
- ユーザに WiFi 環境下でのダウンロードを促す機能
- ダウンロード済み音楽の中からタスクタイマー用の音楽を 1 曲選定

### 2-14, 休憩終了通知機能

休憩時に次のタスク開始時刻を設定し、その時間に通知ポップアップ(iOS/Android のネイティブプッシュ通知)

### 2-15, 次回の楽しい予定機能(要検討)

ユーザのモチベーション維持を目的に「直近の楽しみな予定」を登録し、それを常にホームページに表示することでユーザの短期的なモチベーションアップにつなげる

### 2-15, タスク集中音楽 AI 生成機能 (ユーザが一定数確保できてから)

★**初期リリース時には実装しない**★
ユーザがキーワードを入れるとそのキーワードに応じて 2 分の音楽が自動生成される。
生成された音楽は自分のダウンロードリストに追加され、タスク集中音楽として使用可能。
初月無料ユーザは 1 曲/1 週間、次月より 3 曲/1 週間。

## 3, 非機能要件

- パフォーマンス
  → 主要画面の初回表示は 2 秒以内を目標
- 安定性
  → 致命的クラッシュ率 1% 未満
- セキュリティ
  → パスワード・支払い情報は業界標準の手法で保護。
