# 月間目標機能を削除し、長期目標を設置

## 背景-1 月間目標機能は不要ではないか

以下の点よりユーザは毎月ゴールを決めるのは面倒だと考えるのではないか

- 毎月似たような目標が重複し、入力が面倒
- 各目標を月単位で目標時間を計算、入力するのが面倒
- 週間タスクが月間タスクの約4分の1を占めるため、週間タスクのみの管理の方が楽ではないか
- 月替りのたびに週間タスクの紐付けも丸ごと行わなくてはならず面倒
- ユーザは1年に一回の頻度で中期目標を見直すのが現実的ではないか(毎月の見直しは面倒)
- ユーザが月間目標の記載をしたければ、週間タスクに「今月ielts7.5をとるための最後の勉強」等記載すれば事足りるのではないか
- 週間タスクの作業時間を年間目標に積み上げて、年間単位で自分の努力や軌跡を見れれば十分ではないか(本当に毎月見直す？)

## 背景-2 理想の自分と年間目標の期間のギャップがありすぎる

例えば理想の自分が「カナダで子供と一緒に一軒家に住みたい」だとして、
「いつまでに一人目の子供を作るのか」「いつまでに家が欲しいのか」「カナダで永住権は何歳までに」
などの長期目標が立てれない。
年間目標では上の３つをカバーできない。
上の三つを”長期目標”と記載した上で「では今年は副業で◯万円達成しよう」や「カナダ永住のためにielts7を取ろう」とかを立てられる

## 要件

### １、月間目標を廃止する。

データベースには引き続き月間目標を残し、コードベースでも記載は残す。(今後月間目標再度導入の可能性が０ではないため)
ただアプリ機能としては一切を取り除き、他のデータやページ構築とも一切依存関係を作らない

- 各週間タスクと紐づけるのは月間目標ではなく年間目標
- 年間目標が削除された時はcascadeでまず紐づく週間タスクを削除してから年間タスクを削除する(引き続きユーザにポップアップで事前通告する)
- 週間タスクのタスクタイマーが実績記録を計測したら紐づく年間タスクに積み上げられる(月間目標は経由しない)

### ２、長期目標ページを追加する

現行の６つの機能ページの「月間目標」の抜けた穴を「長期目標」が埋める。
順番としては1段目に「理想の自分」「長期目標」2段目に「年間目標」「週間タスク」3段目に「タスク集中音楽」「休憩通知」
長期目標の機能は以下の通り

- 土台の機能は「理想の自分ページ」と同じ(追加、削除、更新、順番入替)
- タイトルカードには「タイトル」「現在地: 年齢or年号」(現在地がnullの場合は非表示)
- インプットモーダル項目は「現在地(userテーブルで保持。タイトルでの表示、全てのカードで必ず同じ値を持つ、nullable)」「いつまでに」「長期目標」
  「現在地」と「いつまでに」は自由形式で入力可能。Placeholderで「(例)25歳、2035年まで」などを表示しガイドする。
- 各カードは1列目に「いつまでに」2列目に「長期目標内容」を入れる。3段目には「完了ボタン」「編集ボタン」「順番入替ボタン」
- 完了ボタンの仕様は「年間目標ページ」と全く同じ
- データは理想の自分と同様にどのデータとも紐づかず、作業時間などの積み上げも行われない

## データ構造

### 月間目標データはそのまま

以下月間目標データはそのまま残す。
ただアプリ内では一切使用しないので他データとの依存関係などは残さない。

```
Table monthly_goals {
yearly_goal_id uuid [not null, ref: > yearly_goals.id]
id uuid [pk]
user_id uuid [not null, ref: > users.id]
month int [not null]
description varchar [not null]
estimated_time_month int //月間ゴール目標時間
accumulated_time_month int // 紐づく週間タスクから積み上げられる
"order" int // ソート用
created_at timestamptz
updated_at timestamptz
    Indexes {
      (user_id, month)
      (yearly_goal_id)
    }
}
```

### 新しく長期目標データスキーマを作成

以下のスキーマで長期目標データを管理

```
Table long_term_goals {
id uuid [pk]
user_id uuid [not null, ref: > users.id]
until_when varchar [not null]
description varchar [not null]
is_done boolean
"order" int // ソート用
created_at timestamptz
updated_at timestamptz
    Indexes {
       (user_id, "order")
    }
}
```
